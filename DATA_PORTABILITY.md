# Переносимость данных DONARIUM

## Что уже реализовано

PostgreSQL хранит каталог и метаданные, а не содержимое STL, 3MF или архивов. Миграция `db/migrations/001_initial.sql` создаёт товары, категории, теги, ресурсы и связи. UUID товара и ресурса сохраняются при переносе; SKU уникален, но не используется как внешний ключ. `external_links` отдельно связывает карточку с идентификатором внешней системы, например SKUFnya. Подключений к базе магазина нет.

Ресурс содержит имя, MIME-тип, размер в байтах, SHA-256, версию и один из двух адресов:

- `external_url`: HTTP(S)-ссылка на файл другого сервера;
- пару `storage_id` + `relative_path`: стабильный идентификатор хранилища и относительный путь с `/`.

В первом этапе интерфейс отображает метаданные файлов. Внешние HTTP(S)-ссылки можно открыть, если они заданы; серверные сканирование, загрузка и скачивание по относительному пути ещё не реализованы. Демонстрационные карточки показывают имена предполагаемых файлов, но оригиналов в проекте нет. Размер и хеш пока могут быть `null`: приложение не выдаёт их за проверенные значения.

`storage_locations` хранит UUID, технический ключ, название и тип хранилища. Корневой путь, адрес сервера и секреты не входят в запись и должны задаваться конфигурацией при подключении адаптера. Перенос библиотеки меняет эту конфигурацию, а не тысячи относительных путей. Проверка схемы отклоняет абсолютные пути, обратные слеши и сегменты `.`/`..`; перед чтением будущий файловый адаптер обязан дополнительно проверять реальный путь и символьные ссылки.

Библиотеку более 2 ТБ на другом сервере копировать в DONARIUM не требуется. На текущем этапе практичный адрес ресурса — постоянная HTTP(S)-ссылка этого сервера, доступная устройству, которое открывает карточку. Недоступность удалённого файла не удаляет карточку и не доказывает повреждение файла. DONARIUM не обращается к этим адресам с сервера и не скачивает их для проверки. Приватные адреса допустимы для LAN; учётные данные и временные подписанные URL не следует хранить как постоянные ссылки.

Миграции запускаются явно через `npm run db:migrate`, с транзакцией на файл, advisory lock и таблицей `schema_migrations` с SHA-256. Применённые миграции изменять нельзя: создаётся следующий SQL-файл. Инструменты записи требуют отдельную БД с именем `donarium` или `donarium_<суффикс>` и `DB_MIGRATION_CONFIRM=donarium`. Это защита от случайного выбора базы соседнего проекта, а не замена проверки оператора. Приложение не выполняет миграции при запуске.

## Предлагаемый открытый формат экспорта: версия 1

**Это спецификация для следующего этапа. Команд и API экспорта/импорта пока нет.** SQL-дамп уже можно получить штатными средствами PostgreSQL, но это отдельный механизм резервного копирования.

Полный пакет предполагается в обычной директории или ZIP:

```text
donarium-export/
  manifest.json
  products.ndjson
  assets.ndjson
  categories.ndjson
  tags.ndjson
  product-categories.ndjson
  product-tags.ndjson
  storage-locations.ndjson
  external-links.ndjson
  files/                    # только если оригиналы включены явно
```

`manifest.json` содержит `format: "donarium-library"`, `schemaVersion: 1`, UUID экспорта, время UTC в ISO 8601, версию приложения, число записей, список файлов метаданных с SHA-256 и признак включения оригиналов. NDJSON — UTF-8, один JSON-объект на строку; формат позволяет обрабатывать большие каталоги потоком. Имена полей предполагаются в `camelCase`, как в общих контрактах `packages/shared/src/index.ts`; JSON Schema должна быть добавлена вместе с реализацией экспорта.

Пример записи ресурса:

```json
{
  "id": "00000000-0000-4000-8000-000000000001",
  "productId": "11111111-1111-4111-8111-111111111111",
  "kind": "model",
  "name": "vase.stl",
  "mediaType": "model/stl",
  "sizeBytes": "2147483648",
  "sha256": null,
  "version": "1.0",
  "storageId": null,
  "relativePath": null,
  "externalUrl": "http://files.example.test/models/vase.stl"
}
```

`sizeBytes` — десятичная строка либо `null`, поскольку PostgreSQL `bigint` может превышать точность JavaScript `number`. SHA-256 — 64 строчных шестнадцатеричных символа либо `null`, если не вычислен. Времена — UTC ISO 8601. Секреты, пароли, временные токены и абсолютные серверные пути в пакет не входят. CSV будет вспомогательным плоским экспортом товаров, а не форматом полного восстановления связей.

При включении оригиналов пакет должен сохранять таблицу соответствия ресурса файлу, относительные пути и контрольные суммы. Для удалённого сервера экспорт по умолчанию содержит только ссылки; включение его 2 ТБ данных требует отдельной явной операции. Переименование или перенос файлов на том сервере потребует обновления соответствующего адреса либо настройки постоянных URL на стороне файлового сервера.

## Требования к будущему импорту

Импорт сначала проверяет версию схемы, размеры, хеши, уникальность UUID/SKU, все внешние ключи и безопасные пути. ZIP-архивы нельзя распаковывать без защиты от path traversal, символьных ссылок и чрезмерного распакованного размера. Неизвестная версия отклоняется до записи. Предварительный отчёт показывает конфликты и недоступные оригиналы. Политика конфликтов задаётся явно; тихая перезапись реальных карточек запрещена.

Метаданные импортируются транзакционно, с сохранением UUID и отметкой конкретного импорта. Файлы сначала попадают во временную область и проверяются. Поскольку файловая система и PostgreSQL не образуют общую транзакцию, нужен журнал и возможность безопасного повторения после сбоя. Для восстановления в чистую библиотеку импорт должен проходить без ручного исправления связей. Обязательный критерий будущей реализации: export → import в пустую БД → сравнение количества, UUID, связей и SHA-256 оригиналов.

## Резервное копирование и восстановление сейчас

Для настоящего каталога необходимо регулярно сохранять отдельным заданием:

1. Дамп **только выделенной БД DONARIUM** через `pg_dump --format=custom` с версией клиента не ниже версии сервера. Адрес и пароль передаются через защищённую конфигурацию PostgreSQL (`PGSERVICE`/`.pgpass`), а не пишутся в историю команд.
2. Оригиналы и фотографии на файловом сервере через его существующий backup/snapshot. Дамп DONARIUM не содержит удалённые 2 ТБ и не заменяет их резервную копию.
3. Привязку UUID/ключей хранилищ к адресам и корням, безопасно сохранённую конфигурацию и версию приложения/миграций.

Пример после настройки сервисов `donarium` и `donarium_restore` в `~/.pg_service.conf`:

```bash
pg_dump --dbname='service=donarium' --format=custom --file=donarium.dump
pg_restore --dbname='service=donarium_restore' --no-owner --no-acl donarium.dump
```

Восстановление проверяется в новой отдельной базе, не поверх SKUFnya или действующей библиотеки. После восстановления требуется проверить количество карточек и ресурсов, несколько UUID-связей и доступность ссылок с клиентского устройства. Для полного будущего каталога нужен согласованный снимок метаданных и оригиналов либо временная остановка операций записи. В текущем приложении HTTP-интерфейс каталога доступен только для чтения.
