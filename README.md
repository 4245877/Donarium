# DONARIUM

Персональная цифровая библиотека моделей для 3D-печати, проектов и связанных материалов. Основа приложения: реальный интерфейс и API, отдельный демонстрационный каталог, рабочий PostgreSQL-адаптер и миграции. Оригинальные STL/3MF не включены. База и сервисы SKUFnya не используются.

## Стек и требования

TypeScript, React 19, Vite 7, Fastify 5, PostgreSQL 16, node-postgres (`pg`), npm workspaces. Все зависимости локальные, lockfile включён. Нужны Docker с Compose **или Node.js 22.12+ (рекомендуется поддерживаемая ветка 22/24 LTS)** и npm. Системный Node.js 20 на обследованном сервере не обновлялся; production работает в Node.js 22 Docker-контейнере.

## Быстрый production-запуск (демо, без БД)

```bash
cd /home/hpelitdesk/apps/Donarium
cp -n .env.example .env
chmod 600 .env
# Укажите свой LAN-IP в HOST; на обследованном сервере это 192.168.0.151.
docker compose up -d --build
```

Открыть **http://192.168.0.151:4180**. Если адрес сервера изменился, обновите `HOST` в `.env` и пересоздайте контейнер: `docker compose up -d`. Порт 4180 выбран после проверки занятых портов. Внутри контейнера Fastify слушает `0.0.0.0:4180`, наружу Compose публикует его только на `HOST`. Frontend и `/api/v1/*` используют один адрес; браузер не обращается к localhost сервера.

```bash
docker compose ps
docker compose logs --tail=100 app
curl -f http://192.168.0.151:4180/health
docker compose restart app
docker compose down
```

`restart: unless-stopped` обеспечивает возврат контейнера после перезапуска Docker/сервера, если Docker запускается автоматически. Проверить: `systemctl is-enabled docker`. Другие Compose-проекты не затрагиваются. Команда `down` относится только к проекту `donarium`; не добавляйте `-v` для базы с реальными данными.

## Локальная разработка

Сначала активируйте Node.js 22.12+ / 24 LTS своим менеджером версий. DONARIUM не требует глобальных npm-пакетов.

```bash
npm ci
cp -n .env.example .env
npm run dev
```

Vite слушает `HOST:DEV_WEB_PORT` (4180), API — только `127.0.0.1:DEV_API_PORT` (4181). Vite проксирует `/api` и `/health`. Для dev порт 4180 должен быть свободен: предварительно `docker compose stop app`. Ctrl+C завершает оба процесса. API-port можно изменить в `.env`, proxy подхватит его.

```bash
npm run build       # shared → frontend → backend
npm run typecheck   # приложения, общий контракт, CLI и API-тесты
npm test           # API/безопасность; PostgreSQL-тесты пропускаются без TEST_DATABASE_URL
npm start          # production без Docker; сначала выполните build
npm run test:e2e   # Playwright: нужен запущенный сервер и установленный Chromium
```

Интеграционные тесты дополнительно запускаются при `TEST_DATABASE_URL` на предварительно мигрированной и заполненной примерами **отдельной тестовой БД** `donarium_test` / `donarium_test_<suffix>`. Тестовый URL не считывается из обычного DATABASE_URL; тесты намеренно откажут для других имён. Тесты изменений метаданных откатывают транзакции.

Для браузерных проверок: `npx playwright install chromium`, затем `BASE_URL=http://192.168.0.151:4180 npm run test:e2e`. Это установка только тестового браузера. Альтернатива без установки браузера на сервер — контейнер `mcr.microsoft.com/playwright:v1.56.0-noble` с монтированием checkout и `--network host`.

## PostgreSQL: отдельная пустая база

Деморежим `DATA_MODE=demo` не подключается к PostgreSQL даже при наличии `DATABASE_URL`. Для реальных данных выберите `DATA_MODE=postgres`; автоматического переключения на демо при ошибке базы нет.

1. В `.env` задайте новый `POSTGRES_PASSWORD` (случайный, без повторного использования паролей SKUFnya). Для простоты URL используйте hex-пароль, например результат `openssl rand -hex 32`.
2. Поднимите только независимую БД:

   ```bash
   docker compose -f compose.yml -f compose.postgres.yml up -d db
   ```

3. При Node.js 22+ примените миграции с **проверенным адресом отдельной базы**:

   ```bash
   # Пароль подставьте локально; не сохраняйте команду с секретом в Git.
   DATABASE_URL='postgresql://donarium:YOUR_NEW_PASSWORD@127.0.0.1:5548/donarium' DB_MIGRATION_CONFIRM=donarium npm run db:migrate
   # Необязательно: примеры только в совершенно пустую библиотеку.
   DATABASE_URL='postgresql://donarium:YOUR_NEW_PASSWORD@127.0.0.1:5548/donarium' DB_MIGRATION_CONFIRM=donarium npm run db:seed
   ```

4. Для Docker-приложения задайте в `.env` `DATA_MODE=postgres` и `DATABASE_URL=postgresql://donarium:YOUR_NEW_PASSWORD@db:5432/donarium`, затем:

   ```bash
   docker compose -f compose.yml -f compose.postgres.yml up -d --build
   ```

Для приложения без Docker адрес БД — `127.0.0.1:5548`. База слушает с хоста только loopback; её порт не публикуется в LAN. Миграции требуют `DB_MIGRATION_CONFIRM=donarium` и имя БД `donarium` / `donarium_<suffix>`. Seed откажет, если библиотека непустая. Миграции не запускаются автоматически при старте API. Не используйте URL, сеть или учётные данные магазина.

## LAN и безопасность

Проверить IP: `ip -br -4 addr`; порт: `ss -ltnp`. На компьютере/телефоне в той же сети откройте `http://<HOST>:4180`; гостевой Wi-Fi с изоляцией устройств может запрещать соединение. Не настраивайте проброс порта роутера, публичный reverse proxy или туннель к DONARIUM. Если доступ не проходит, проверьте `sudo ufw status verbose` и межсетевые правила; приложение не меняет firewall. При необходимости разрешайте **только фактическую LAN-подсеть** после проверки политики сервера. Docker использует собственные сетевые правила, поэтому одно состояние UFW не доказывает доступность или закрытость Docker-порта.

Сейчас API только для чтения: нет административных маршрутов, загрузки или удаления. Авторизация администратора должна появиться до добавления операций записи. Доступ к каталогу в доверенной LAN пока без входа. Секреты — только в игнорируемом `.env`; `.env.example` их не содержит. Публичная папка содержит только frontend и собственные SVG-иллюстрации. Ни корень файлового архива, ни удалённый сервер не сканируются и не проксируются.

## Что доступно

- Главная, каталог, карточка, страница состояния системы; адаптация к телефону.
- Шесть демозаписей из API, поиск по названию/SKU/описанию/тегам, категории, сортировка, серверная пагинация.
- Список ресурсов: версия, тип, путь, размер и SHA-256 (неизвестные значения честно `null`). HTTP(S)-ссылки открываются напрямую, если они внесены в PostgreSQL; демофайлы отсутствуют.
- PostgreSQL-схема, индексы, адаптер чтения, защищённые CLI миграций и заполнения примерами.

Редактирование, авторизация, сканирование, проверка файлов, загрузка, архивное скачивание, импорт/экспорт и 3D-просмотр пока не реализованы. Параметр `EXTERNAL_STORAGE_BASE_URL` валидируется и отражает конфигурацию; разрешение `storageId + relativePath` в рабочую ссылку — следующий этап. Сейчас работают прямые `externalUrl`, а относительные пути показываются как метаданные.

## Echidna — цифровое Святилище

Интерфейс обновлён в эстетике Эхидны: фарфоровая светлая тема, графитовая навигация, локальная аниме-иллюстрация, мягкие анимации и альтернативная тема «Лунная ночь». Поиск, фильтры и карточки используют прежний API.

Личное пространство (`/favorites`, `/collections`, `/activity`, `/settings`) добавляет избранное, создание/изменение/удаление коллекций, выбор моделей, историю действий, настройки имени, темы, анимаций и плотности. Эти данные хранятся в localStorage браузера; JSON-экспорт и проверяемый импорт доступны в настройках. Операций записи в серверный каталог и серверной авторизации по-прежнему нет. Резервная копия содержит личные метаданные, без оригиналов 3D-моделей.

Для этого проекта используйте только локальное развёртывание. Не создавайте и не обновляйте облачные публикации без отдельного явного запроса пользователя.

Развёртывание выполняется локально через Docker Compose на `http://192.168.0.151:4180`. Интерфейс использует API этого же приложения. Отдельная облачная сборка и её режим данных удалены из проекта. Дизайн и границы реализации описаны в [docs/ECHIDNA_DESIGN.md](docs/ECHIDNA_DESIGN.md).

Новые проверки: `tests/browser/workspace.spec.ts`. На хосте с уже установленным Chromium можно передать `PLAYWRIGHT_CHROMIUM_EXECUTABLE=/absolute/path/to/chrome`. После пересборки production-интерфейса перезапустите Fastify, чтобы он зарегистрировал новые файлы `dist/assets`; Docker Compose делает это при пересоздании контейнера.
