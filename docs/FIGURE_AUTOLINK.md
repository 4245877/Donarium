# Консервативная массовая привязка фигурок

Обслуживание использует работающий `saveFigureFile`: `assets.file_id`, роль `figure` и относительный путь в `storage_files`. Образы приложения, схема БД, поля карточек, прежние вложения и оригиналы не изменяются. Узкий адаптер пропускает штатное обновление `products.updated_at`, чтобы сохранить все столбцы товаров, как требует эта операция. Остальные проверки и журналирование выполняет штатный механизм.

## Порядок

1. `python3 scripts/figure-link-admin.py backup backups/<уникальное-имя>` — свежий custom dump, снимок всех таблиц, фактическое восстановление во временную БД и полное сравнение строк. Временная БД удаляется.
2. `python3 scripts/figure-link-server-audit.py var/qa/<запуск>` — чтение оглавлений библиотеки непосредственно на `.141`. Во временный `/tmp` передаётся только программа чтения архивов и скрипт; они удаляются. Оригиналы не извлекаются и не копируются. Остальные модельные каталоги проверяются отдельно; bind-представления одного каталога не считаются дубликатами.
3. `python3 scripts/figure-link-match.py backups/<имя>/before.json var/qa/<запуск>/server-audit.ndjson var/qa/<запуск>/plan.json` — полный анализ без записи в БД.
4. Проверить отчёт и репрезентативную выборку, выполнить `python3 tests/figure-link-match.test.py`. Пробная реальная привязка: `python3 scripts/figure-link-execute.py rehearse <plan.json> <rehearsal.json> --sample-ids <sample-ids.json>`. Транзакция откатывается, полное содержимое таблиц должно совпасть с исходным.
5. `python3 scripts/figure-link-execute.py apply <plan.json> <apply.json>` — только строки `ready`, одной serializable-транзакцией. Любое изменение БД после анализа, иная существующая связь или изменение оригинала блокирует запись. Существующие вложения и несвязанные записи реестра сравниваются полностью. Все столбцы всех товаров проверяются на неизменность.
6. Повторить apply с тем же планом и другим файлом результата: ожидаются 0 новых связей и неизменная БД. `node scripts/figure-link-verify.mjs var/qa/<запуск>` проверяет все карточки через API, чтение 16 байт каждого связанного оригинала, редактор и мобильную ширину.

## Достоверность

Исходные имена берутся из описания, всех импортированных источников и прежних внешних вложений. Они должны согласовываться. NFKC, регистр и разделители нормализуются; значимые слова, автор, версии, цифры, поддержка, NSFW и явно заданное расширение сохраняются. Несколько файлов с одинаковым нормализованным именем не разрешаются выбором первого.

Помимо уникального исходного имени необходимы доступность обычного файла через NFS guards, согласованные размер/SHA-256/неизменность прежней описи, читаемое оглавление, реальные модельные файлы и подтверждение персонажа/версии в их путях. Название студии, общая франшиза и нечёткое сходство не служат достаточным подтверждением. Явные противоречия категории/тайтла и содержимого блокируют запись. `one_piece.stl` трактуется как цельная сетка, а не название франшизы. Версии одного персонажа с недостаточно конкретным исходным именем, вложенные архивы без доступных моделей и непроверенные многотомники остаются на ручной проверке.

Неизменность полной SHA-256-описи подтверждается размером и mtime/ctime всех архивов; новые полные хеши 394 ГиБ заново не вычисляются. Чтение оглавлений не является проверкой CRC каждой распакованной детали или геометрии каждой сетки. Эти ограничения отражаются в итоговом отчёте.

## Откат

Каждый запуск записывается в `storage_operations` с видом `figure-autolink`, SHA-256 плана и точными состояниями изменённых строк до/после. События штатного `attach` и отдельные `figure-autolink` связаны с UUID операции. Полный backup сохранён отдельно.

Проверка точечного отката без фиксации:

```bash
python3 scripts/figure-link-execute.py rollback <plan.json> <rollback-verification.json> --operation-id <UUID> --verify-rollback-only
```

Реальный откат выполняется той же командой без `--verify-rollback-only`. Он отказывается работать, если связь или соответствующая запись реестра изменены после операции, сохраняет журнал аудита и восстанавливает только созданные/обновлённые связи и проверочные метаданные. Оригиналы не затрагиваются. Прежние `storage_matches`, описания и ссылки Google Drive сохраняются: старый механизм сопоставлений заменяет внешние ссылки и не используется для этой операции с полем «Файл фигурки».
