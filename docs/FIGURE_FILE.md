# Поле «Файл фигурки»

Текущее состояние: 598 карточек, 463 подтверждённые привязки и 135 карточек для ручной проверки. Последующий аудит исправил сохранение переиспользованных вложений и обновил рабочий образ на `donarium-audit:20261028-technical`; [результаты и откат](TECHNICAL_AUDIT_2026-10-28.md).

## Анализ и выбранное решение

Приложение состоит из React/TypeScript, Fastify и PostgreSQL. Оригиналы уже подключены к API по NFS: `192.168.0.141:/library` → `/mnt/donarium/library` на хосте → `/app/storage/library` в рабочем контейнере. В `compose.nfs.yml` этот каталог доступен только для чтения. `storage_locations` задаёт логический ключ, `storage_files` хранит относительный путь и метаданные, `assets` связывает файл с товаром. Существуют авторизация владельца, проверка Origin, защита путей и NFS guards.

Повторная загрузка, SMB из браузера и хранение абсолютного UNC-пути не нужны. Поле использует существующий реестр: `assets.metadata.role = "figure"`, `file_id` и относительный путь в `storage_files`. Миграция `007_figure_file.sql` добавляет уникальный индекс: у товара не больше одной активной связи с этой ролью. Данные существующих карточек и пути не преобразуются; прежние вложения можно выбрать повторно без дублирования.

Создание/редактирование карточки и изменение связи выполняются одной транзакцией. При ошибке проверки файла или других полей изменения откатываются. Неизменённое файловое поле не отправляется: описание товара можно редактировать и при временно недоступном оригинале. Явный `null` снимает привязку. Связь, созданная специально для поля фигурки, удаляется при замене или отвязке; реестр и оригинал остаются. Если выбран файл из уже существующих вложений, запись переиспользуется без дублирования и получает служебную отметку `figure_reused_attachment`. При замене или отвязке снимаются роль и эта отметка; прежнее вложение, его UUID и остальные метаданные сохраняются. Проверка этого поведения добавлена в `tests/figure.integration.test.ts`.

## Работа в интерфейсе

В новой или редактируемой карточке откройте «Файл фигурки» → «Выбрать файл фигурки». Можно менять разрешённое хранилище, переходить по папкам и цепочке пути, искать по имени или части пути во вложенных папках. Показаны только модели, исходники, архивы и папки. Поиск работает по настоящей файловой системе, включая ещё не зарегистрированные файлы.

Рядом с файлом доступны просмотр и выбор. После выбора показаны имя, логический путь, размер и результат проверки доступности. «Заменить файл фигурки» и «Удалить привязку» меняют форму; изменения применяются кнопкой «Сохранить карточку». «Отмена» сохраняет прежнюю связь. В сохранённой карточке есть отдельный блок просмотра файла.

Для ASCII/binary STL до 32 МиБ работает встроенный вращаемый просмотр: мышь, касание, стрелки и масштаб. Крупные сетки отображаются с упрощением. ZIP/RAR/7z и другие форматы показывают сведения и ссылку на скачивание оригинала для открытия в архиваторе/3D-программе. Архивы на сервере не распаковываются. Байты STL читаются непосредственно в память браузера; серверная копия не создаётся.

## API и безопасность

- `GET /api/v1/storage/browse?root=LIBRARY&path=...&figuresOnly=true` — папки, фильтр форматов, пагинация.
- `GET /api/v1/storage/figure-search?root=LIBRARY&path=...&q=...` — поиск от двух символов, без учёта регистра, включая кириллицу.
- `GET /api/v1/storage/figure-file?root=LIBRARY&path=...` — сведения и проверка чтения обычного файла.
- `GET /api/v1/storage/figure-file/download?...` — поток оригинала с HTTP Range.
- `GET /api/v1/storage/figure-file/preview?...` — STL, максимум 32 МиБ.
- В `POST/PUT /api/v1/products` поле `figureFile: {root, path}` выбирает файл, `figureFile: null` отвязывает, отсутствие поля сохраняет прежнюю связь.

Все endpoints защищены существующей сессией владельца. Браузер не получает физические пути и сетевые credentials. Используются только настроенные корни; внутреннее хранилище INVENTORY скрыто и запрещено для выбора, поиска и просмотра. Абсолютные пути, UNC, обратные слеши, `..`, управляющие символы и символические ссылки отклоняются. Компоненты пути открываются через дескрипторы с `O_NOFOLLOW`; специальные файлы запрещены. Перед сохранением файл проверяется повторно; известное повреждение/несовпадение размера блокирует привязку.

Поиск ограничен 200 результатами, 10000 просмотренными элементами, глубиной 30 уровней и проверкой времени между файловыми операциями (5 секунд). При неполном обходе интерфейс предлагает уточнить запрос или папку. Недоступные вложенные папки отмечаются как пропущенные. Hard NFS может ждать сервер внутри системного вызова дольше этого времени: ограничение поиска не является тайм-аутом ядра. Guards сохраняют существующее поведение: отсутствующий сетевой диск не подменяется локальной папкой.

JSON/ZIP сохраняют роль вместе с метаданными assets. CSV добавляет роль в `assets_json`. Проверено восстановление роли и UUID из полного экспорта; сама привязка новых файлов при обычной работе никаких оригиналов не копирует.
