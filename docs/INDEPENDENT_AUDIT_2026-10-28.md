# Независимый технический аудит Donarium — 28 октября 2026

## 1. Оценка и границы результата

Проверен локальный checkout `04d2fb1`, приложение 0.3.0, рабочие PostgreSQL 16 и HTTP API на `.151`, NFS-клиент, конфигурация и диск `.141`. Внесены исправления в исходники, добавлены регрессии и собран отдельный Docker-образ `donarium-audit:20261028`. **Рабочий контейнер остаётся на прежнем образе: исправления ещё не развёрнуты.** Коммиты, push, производственные миграции, перезапуски приложения, переключения mounts и изменение карточек не выполнялись.

Исходные 47 автоматических тестов прошли до изменений, но новые воспроизведения обнаружили ошибки сохранения связей, истории, восстановления и обработки отказов. Итог: 58 автоматических тестов, 12 браузерных сценариев, типизация и сборка проходят. Это проверка конкретных свойств, а не доказательство отсутствия остальных ошибок.

**Открытый подтверждённый дефект recovery:** поздний отказ mount может возобновить приложение после более раннего обычного `systemctl stop`. Для надёжной остановки обслуживания требуется `disable --now`; текущую схему нельзя считать полностью выполняющей требование «любой ручной stop исключает последующий автозапуск».

Основные доказательства: `var/qa/independent-audit-20261028/`. Каталог исключён из Git; внутри есть маленькие свежие dump/ZIP метаданных с пользовательскими данными, они не предназначены для публикации. Полные копии оригинальной библиотеки не создавались.

## 4. Проверенные подсистемы

### API, файлы, безопасность

Проверены регистрация, hash/staging/promotion, параллельная дедупликация, повторное использование несколькими товарами, замена с сохранением asset UUID, отвязка, Range/HEAD/416, ZIP карточки, missing/corrupt, прерывание источника и повтор загрузки, импорт папок, экспорт/restore v1/v2 и неоднозначный COMMIT.

Запись файла до COMMIT может оставить готовый непривязанный объект после отката БД. Код сохраняет этот объект; inventory/recovery позволяют его обнаружить. Это сознательный выбор сохранности байтов, а не полная атомарность между NFS и PostgreSQL. Общие файлы при удалении связи физически не удаляются. Прерывание потока проверено новым тестом: registry/attachments не добавляются, staging пуст, retry успешен.

26 HTTP-проверок рабочего сервиса прошли: отсутствие cookie даёт 401 для каталога, файлов, изображений и export; ошибочный UUID — 400; traversal и неизвестный root отклонены; служебные файлы/backup не опубликованы; чужой Origin отклонён 403 до записи; строка SQL-инъекции остаётся поисковой строкой; Range 206, ошибочный Range 416, HEAD без тела. Файл скачивания имеет attachment и nosniff. Полный список — `production-api.json`.

Статически и тестами проверены O_NOFOLLOW и открытие компонентов через directory FD, запрет символьных ссылок/спецфайлов, безопасные ZIP paths, лимиты распаковки, checksums, уникальность UUID и ссылочная валидация. Политика XSS: React выводит текст, URL фильтруются, CSP запрещает произвольный script, SVG/HTML-загрузки выдаются attachment; inline разрешён для растровых типов. Классификация по расширению не является подтверждением содержимого файла; sharp ограничивает число пикселей. Произвольное чтение `/etc/passwd` через проверенные маршруты не удалось.

`npm audit` на дату проверки: 0 известных advisory для установленного lockfile, 259 зависимостей в отчёте. Это не аудит всех зависимостей и не сканирование CVE системных пакетов контейнера. Текущие ADMIN_PASSWORD и пароль БД не найдены в Git history; `.env` не tracked, права 0600. Секреты в отчёты не выводились. Проверка ищет известные текущие секреты, а не доказывает отсутствие любого когда-либо использовавшегося секрета.

### PostgreSQL и совместимость

Рабочие запросы выполнялись в `REPEATABLE READ READ ONLY`. Проверены схема, FK/unique/check, индексы и валидность constraints/indexes. Нет обнаруженных разрывов assets ↔ registry, повторных product/file links, неверных covers, локальных assets без file_id. SQL параметризован. Проверены migration checksum и добавочный характер 006; реальные миграции повторно не запускались на production. Все миграции многократно применены к новым тестовым схемам; мигратор хранит checksum и запрещает изменение уже применённого SQL.

Сохранено 601 external_link для 598 товаров. Это подтверждает сохранность текущих исторических метаданных, но не доказывает полноту когда-то существовавшего Google Drive: исходного независимого полного экспорта Drive для такого сравнения нет.

### NFS, диск, Docker, systemd

На `.141` прочитаны действующие exports и зависимости nfs-server, подтверждены `/srv/data` → `/dev/sda1`, ext4, UUID `76d90fb2-6d59-4fdb-8280-81154e6c93d9`. Корни представлены отдельными bind mounts; `root_squash`, sync, sec=sys, ограничение клиента `.151` присутствуют. Library и inventory readonly, uploads/work writable. В Docker — соответствующие bind mounts с rprivate, library/inventory readonly. Приложение работает непривилегированным node; rootfs readonly, capabilities сброшены, no-new-privileges, ограниченные логи.

Клиентские mounts — NFSv4.2/hard/nosuid/nodev/noexec. Guards проверяют kernel mount source и маркер UUID перед операциями. Изолированные отрицательные тесты доказывают отказ до создания файлов при отсутствии guard или подмене NFS локальным каталогом, даже со скопированным маркером. Точки монтирования и BindsTo дополнительно препятствуют fallback. Настоящие mounts не снимались: проверка не моделирует все возможные гонки kernel/mount namespace, аварийное питание и физический отказ диска.

Исходный systemd recovery-тест повторён: блокировка без storage, несколько retries, позднее появление storage, остановка текущего retry, recovery работающего приложения, disable/explicit resume — проходят. Расширение обнаружило A15. Действующий firewall `.141` в ядре прочитать не удалось: `sudo -n nft` требует интерактивной аутентификации. Его unit и исходник проверены, запрос пароля не выполнялся. Фактические разрешённые/запрещённые подключения с другого компьютера не проверялись.

Chromium проверил desktop и viewport 390×844: поиск/URL/перезагрузку, фильтры, навигацию, ошибки API/retry, темы/клавиатуру, создание/редактирование/фото/удаление, файловый реестр, reuse/replace/unlink, подтверждение соответствия, folder import, JSON/CSV/полный ZIP/restore и частичную загрузку. Оформление сохранено. Физический телефон, Firefox/Safari, многомесячная эксплуатация не имитировались.

**Ограничение этой репетиции:** для больших архивов QA-адаптер возвращает сохранённый SHA только после строгого совпадения size/mtime_ns/ctime_ns, чтобы не читать 394 ГиБ дважды. Для uploads используется настоящий hash. Первую попытку без адаптера остановили после обнаружения повторного полного чтения; её временные БД/каталог адресно очищены. Поведение реального hash и конфликтов отдельно проверено тестами с настоящими маленькими файлами. Нельзя называть эту репетицию новым полным хешированием всей библиотеки или испытанием восстановления байтов после смерти HDD.
