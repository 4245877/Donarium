Браузерные сценарии проверяют: главную, реальный API, все шесть карточек, поиск по названию и SKU, фильтр категории, сортировку, пустую выдачу, сброс фильтров и страницы за пределами каталога, открытие карточки и прямую перезагрузку её URL, список файлов без фиктивного скачивания, мобильную навигацию на ширине 390 px, отсутствие горизонтального переполнения и загрузку иллюстраций. Отдельный сценарий искусственно возвращает 503 и проверяет восстановление кнопкой «Повторить». В основном сценарии нет JavaScript-ошибок страницы.

Production-контейнер работает от пользователя `node`, с read-only root FS. Порт опубликован только как `192.168.0.151:4180`; автоперезапуск `unless-stopped`, Docker service enabled. После проверок временная тестовая БД с tmpfs удалена. Реальные данные/пароли SKUFnya не использовались. Скриншоты локальной проверки — в игнорируемой папке `var/qa/`.

## Границы проверки

- Физический телефон/ноутбук в LAN не использовался. Выполнен HTTP-тест на сервере через его LAN-IP и Chromium в контейнере на том же сервере. Это не проверка Wi-Fi, маршрутизатора или межсетевого экрана между устройствами.
- `ufw status verbose` требует root; `sudo -n` недоступен без пароля. Правила firewall, роутера, существующих nginx/tunnel и сервисов не менялись. Приложение не публиковалось через облачный hosting и не настраивало интернет-доступ.
- Перезагрузка Ubuntu не выполнялась; проверены политика рестарта контейнера, включённый Docker service и ручной restart.
- PostgreSQL проверен только на отдельной временной `donarium_test`. Основное приложение оставлено в **demo** без подключения к БД.
- Нет нагрузочного теста на сотнях тысяч товаров, проверки удалённых STL-ссылок или реального скачивания 2 ТБ архива. Оригиналы, их размеры/хеши, фоновые задания, CRUD/авторизация и переносимый импорт/экспорт ещё не реализованы.

Команды повторения и включения отдельного PostgreSQL описаны в README.md. Секретный TEST_DATABASE_URL задаётся окружением и не сохраняется в репозитории.


## Локальный редеплой и очистка — 24 октября 2026 года

- Production-образ пересобран командой `docker compose build app`; только сервис `app` пересоздан с ожиданием healthcheck. Контейнер `donarium-app-1` работает и healthy, порт по-прежнему привязан к `192.168.0.151:4180`.
- На рабочем LAN-адресе проверены `/health`, новый HTML-заголовок Echidna, все 4 сценария каталога и 9 сценариев личного пространства. Итого 13 браузерных тестов прошли. TypeScript и 9 API-тестов прошли; 4 PostgreSQL-теста пропущены без отдельного TEST_DATABASE_URL.
- Удалены дубликат облачной сборки, её адаптер `standalone.ts` и условные ветки, старая неиспользуемая главная страница, QA-скрипты/снимки, результаты тестов и временные архивы. Каталоги Sites, Git-метаданные и PDF исключены из Docker build context.
- `.env`, пользовательский PDF, рабочие исходники, изображения, шрифты с лицензиями, зависимости и данные сохранены. Глобальный Docker prune и изменения соседних сервисов не выполнялись.
- По просьбе владельца облачная публикация Sites заменена обработчиком HTTP 410 для всех путей, без кода приложения и ресурсов. Это **не полное удаление проекта**: в текущем коннекторе нет команды удаления сохранённых версий и истории репозитория. Для полного удаления нужен интерфейс сервиса или его поддержка.

Оставшийся облачный объект для полного удаления: `Echidna — цифровое Святилище`, project_id `appgprj_6adbc3d20b148191888f1866e108c823`. Снятие рабочей публикации подтверждено успешным deployment `appgdep_6adc6658e69c81919ed7ad8392d82f8c`; текущая версия содержит только ответ 410 Gone. Идентификатор сохранён здесь для завершения удаления, а не для повторной публикации.

После снятия облачной публикации дополнительно выполнена HTTP-проверка с существующим ключом доступа владельца: текущий адрес и прежний адрес после перенаправления возвращают 410 Gone как для главной страницы, так и для старого URL иллюстрации. Новые ключи доступа не создавались. Временный проверочный скрипт удалён.
